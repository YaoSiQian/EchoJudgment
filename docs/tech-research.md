## 1. 参考游戏研究综述

### 1.1 AI-Native 游戏：生产策略

#### "1001 Nights"（CHI EA '25，Ada Eden）

论文来源：arXiv-2503.09102，*"I Like Your Story!": A Co-Creative Story-Crafting Game with a Persona-Driven Character Based on Generative AI*

**系统架构要点：**
- AI King 角色通过 GLM-4 驱动，使用 Prompt Engineering 编码其"偏好"——贪婪、古典、厌恶现代词汇。King 不是助手，而是有主观评价标准的**裁判**。
- 所有 AI 输出格式化为 JSON：`{ evaluation, continue_story, weapon_keyword, mood }`，便于游戏状态解析。
- Oulipo 式约束（玩家在规则内写作）比开放输入产生更高的创意投入——**限制创造张力**。
- "物化"机制（关键词 → 武器卡）将叙事贡献转化为可触摸的系统资源，形成**叙事-玩法闭环**。

**对《回响》的直接启示：**
1. AI NPC 需要编码的不只是性格，而是具体的**评价标准**（什么样的对话令他们舒适/不安）
2. 所有 AI 响应必须返回结构化 JSON，不接受纯文本叙事——解析游戏状态的可靠性是首要保证
3. 评价选项不应是"自由输入"，而是**精心措辞的约束选择**——每个选项的语气差异就是叙事信息

#### Quest Machina（AI-Native RPG）

**双 AI 流水线策略：**
- LLM 处理所有叙事、对话、世界描述
- 图像生成 AI ���理所有视觉资产（角色、地点、物品）
- 玩家生成的世界序列化为唯一 ID 可分享——内容即传播

**对《回响》的直接启示：**
1. 社媒模式中 NPC 的"发帖配图"使用 **AI 生成的图片描述文字**代替实际图片，Phase 1 不需要图像生成 API
2. 玩家评价历史的摘要哈希可作为未来社区功能的基础（"你的评价画像"）

### 1.2 决策类游戏：机制提炼

#### WILL: 美好世界 / A Wonderful World

**强制差评路径（Mandatory Bad Paths）：**
- 必须经历失败结局才能解锁救赎路径——强迫玩家**承担后果而非绕过**
- 玩家的"上帝视角"（操控他人信件内容）直接将"编辑权力"游戏化
- 每个结局对应的状态机：`片段配置 → 结果ID`，所有结局预先创作，玩家发现路径而非生成

**对《回响》的直接启示：**
1. 第二幕（诱惑期）**必须包含至少一次不可避免的负面后果展示**，才能让道德重量在第三幕成立
2. 评价选项的措辞差异本身是叙事信息——`"给TA一个机会"` vs `"随便"` vs `"TA活该"` 表达的不只是数值差异
3. AI 生成内容时应优先考虑"如何让玩家在做错事之前感觉是对的"

#### 复制品 / Replica

**界面即叙事（Interface as Fiction）：**
- 游戏的全部界面是一个模拟手机 OS——没有独立的"游戏UI层"
- **惯性共谋**：玩家在意识到道德代价之前，已经通过熟悉手势完成了道德行为（滚动浏览私信 = 偷窥）
- 手机界面的熟悉感降低进入摩擦，内容的陌生感则放大后续的不���

**对《回响》的直接启示：**
1. PhoneFrame 内部**绝对不能出现任何传统游戏感 UI 元素**——这是 GDD 支柱3 的技术实现红线
2. 评价按钮的设计语言应来自真实 App 功能键（如微信的"..."长按菜单风格），而非游戏按钮
3. 目标：玩家在意识到"我做了一个评价"之前，动作已经完成——操作流程的自然性就是心理陷阱

#### Life is Strange / 奇异人生

**过程追踪与能力剥夺：**
- 不只记录最终选择，还追踪**撤销频率、思考时长**——这些成为隐藏状态变量
- 先建立"可撤销"的安全感（前四幕），在最终时刻**移除撤销能力**，制造最大心理冲击
- 跨章节因果：选择效果延迟显现，减弱即时反悔冲动，强化因果感

**对《回响》的直接启示：**
1. 追踪玩家在评价选项上的**悬停时长**（`mouseenter` → `click` 间隔），作为"压力承受度"指标输入玩家模型
2. 不可撤销设计需要前置足够的"安全感"阶段做对比——第一幕应该让玩家觉得"这只是个游戏"
3. 后果的跨场景延迟显现是关键体验设计——不要立即反馈所有后果（GDD 已有，需要技术实现保障）

#### Financial Times Climate Game

**线性累加器模型：**
- 复杂反馈只需运行总量 + 每步增量，不需要真正的模拟引擎
- 个性化最终输出（"你的2100年"）比通用结论的情感重量大十倍
- 科学数据通过新闻叙事框架呈现，降低认知门槛，增强可信度
- 技术栈：React + D3.js，部署于静态托管，10周7人团队完成

**对《回响》的直接启示：**
1. 失衡值系统用**简单线性累加器**实现，无需复杂模拟算法（见 GDD 4.4.1 公式）
2. 第四幕的"道德清算"页面应该是**个性化的**——展示玩家自己的评价历史摘要
3. 资讯模式的新闻必须有真实感（来源、时间戳、措辞风格）才有心理重量

## 2. 核心设计决策矩阵

| 决策点 | 选项 | 最终决策 | 依据 |
|--------|------|---------|------|
| AI 输出格式 | 纯文本 vs JSON | **强制 JSON Schema** | 1001 Nights 验证：结构化输出是状态可靠性的基础 |
| 玩家输入方式 | 自由文本 vs 约束选择 | **约束选择（2-4项）** | 1001 Nights + FT Climate：限制创造更深投入 |
| 手机UI内游戏元素 | 允许 vs 禁止 | **严格禁止** | Replica：界面即叙事，游戏感破坏沉浸 |
| 负面后果时机 | 可跳过 vs 强制 | **强制至少一次** | WILL：必须经历失败才有救赎重量 |
| 评价可撤销 | 可撤销 vs 不可 | **绝对不可撤销** | Life is Strange：不可逆性是情感重量的来源 |
| 后果反馈时机 | 即时 vs 延迟 | **混合（40%即时+35%延迟+25%不可见）** | GDD 4.1.3，Life is Strange 跨章节因果 |
| 过程数据追踪 | 仅结果 vs 过程 | **追踪过程（悬停时长等）** | Life is Strange：过程是隐藏状态变量 |
| 失衡值算法 | 复杂模拟 vs 线性累加 | **线性累加器** | FT Climate：简单模型足以产生复杂感 |

## 3. 从参考游戏提炼的技术红线

以下是基于研究确立的不可违背的技术约束：

```
RED-01: PhoneFrame 子组件树内，禁止出现任何非 App 风格的 UI 元素
RED-02: 所有 AI 响应必须通过 JSON Schema 验证，验证失败触发 fallback
RED-03: 评价操作完成后，不得提供任何撤销/取消机制
RED-04: 玩家模型必须记录交互过程数据（时间戳、悬停行为），不只记录结果
RED-05: 第二幕必须包含至少一个强制触发的负面后果展示节点
RED-06: 失衡值使用 GDD 公式的线性累加，不引入随机扰动（保持可预测性）
```
